# Durable Endly action composition

Construct `durable.New(Options{SourceRoot, StorageRoot, MaxUsers, LeaseEpoch}, executor)` and bind `builder.Execute` plus `builder.PreparePlan` through `integration/endly.NewWithOptions`. The lease callback must report an actually held broker fence belonging to the authenticated principal. The builder never invents a production fence.

Each principal owns a fixed Datly host/connector, bounded by MaxUsers (default 16). Capacity exhaustion fails closed. Close shuts down owned hosts after active actions finish; eviction/reopening policy belongs to the server host. There is no product SQL or service/DAO abstraction.

Plan preparation writes a normalized JSON envelope containing immutable typed plan and inputs, then creates the stable run through generated components with confirmed commit evidence. Input maps stay data: `$`, quotes and newlines cannot become workflow source. Capture/security policy must prevent secrets from entering these inputs; use approved references instead.

Mutation execution uses Endly's stable run/plan/step metadata, reloads authorized durable state, checks the immutable typed step and persisted inputs, checks every unresolved run effect, writes one run-CAS/attempt/intent/audit graph and requires `Outcome.CommitConfirmed()` before calling the action executor. Dispatch alone is never verification. The executor must provide an explicit verified result for confirmed outcome and a verified milestone; missing or uncertain receipts persist unknown and fail the Endly action. Explicit notDispatched resolves absent conservatively without granting automatic retry. Cancellation still permits a bounded five-second outcome commit under the original identity.

Stable attempt/effect IDs are hashes of run, plan and step identity. A confirmed effect with persisted verified evidence can return its stored result without native dispatch. Intent/unknown, unverifiable confirmed evidence and absent effects require reconciliation; restarting the builder never clears that barrier. Read-only steps call the scoped action executor without writing effect intents.

Tests exercise actual Endly tasks, generated Datly SQLite components, visible committed intent before fixture dispatch, verified/unknown outcome, simulated process interruption between dispatch and outcome commit, builder restart, replay barriers and cross-principal rejection. They do not establish real macOS/Chrome behavior or full process-kill crash durability. Remaining gates include a generated reconciliation/adoption use case, durable Endly operation IDs/final run state, complete restart reconstruction of Endly sessions/task paths, per-object grants, encrypted artifact/evidence policy and native desktop-fence qualification.

`Builder.StateGet(ctx, principal, runID)` exposes the generated authorized state projection. `Builder.StatePatch(ctx, principal, runID, expectedRevision, variables)` invokes one generated CAS graph and then refreshes the typed projection. Options.StateMutationGuard must hold paused/new runtime admission through commit and refresh; a nil guard returns ErrStatePatchUnavailable. Component hooks independently reject a running run, unresolved ledger and any metadata/status modification. Neither API changes objective, ledger, plan history, checkpoints or milestones. Current live Endly sessions do not automatically adopt patched variables: until a host supplies the safe paused/new refresh integration, production patch fails closed.

Safe status and correlation callbacks are TransitionRun(ctx, principal, runID, expectedRevision, targetStatus) and AttachOperation(ctx, principal, runID, expectedRevision, sessionID, operationID). Transition targets are paused/succeeded/failed/cancelled and require actual runtime inhibition plus no unresolved effects. Correlation rejects a changed established session or operation. Repeating an identical established correlation returns its existing projection. Audit and action event sequences follow the maximum generated durable event cursor rather than assuming a fixed step-to-sequence mapping.

PublishArtifact(ctx, principal, ref) persists immutable metadata only after Options.VerifyArtifact proves the scoped file's immutable bytes/hash/size/type/key ownership. PublishCheckpoint(ctx, principal, runID, expectedRevision, checkpointID, workspace, refs) creates the manifest hash and revision/cursor from durable facts, re-verifies bytes, and invokes one generated publication graph. The host must first hold paused/new runtime admission. These methods now publish valid checkpoints; absent verification and missing/forged metadata still fail closed. Workspace data remains descriptive JSON and is never executed by this package. Capture drift and actual platform restoration remain backend responsibilities.
