# Private credential handoff

Use this route for credential entry in every app that requires login, including
native apps and embedded browser sign-in windows. Computer Use may navigate to
the form and resume public work after verified login. Secret values must remain
inside Mechanize’s private store and recipient transport, never ordinary typing
arguments, clipboard reads, screenshots or agent-visible results. Preserve an
already signed-in session when it satisfies the task.

Use the qualified private form adapter when available. Clipboard fallback must
verify an empty masked field, write and validate the fixed synthetic probe `x`,
remove it, and confirm emptiness before releasing the credential. Retain exact
recipient/focus authority at paste dispatch; verify delivery privately and clear
the owned clipboard item even on failure. A verified fill is separate from
submission and successful login. Qualify each native or web adapter; the common
API alone does not establish support for every app. Do not sign an app out for a
test until its private re-entry path is qualified.
For native masked controls, use qualified character-count metadata to confirm
empty → one synthetic character → empty and the post-paste structure. Do not
require plaintext read-back or interpret matching counts as password equality.
Only the subsequent app/account state can establish successful login.

Use the already authenticated session if sufficient. Otherwise confirm the intended exact origin and account context from the user task. For Mechanize private entry, retrieve the live desktop skill and credential tool schemas. Prepare the current origin/tab, inspect the opaque preparation status, apply once, and submit once only when the returned state permits it. Never put a password, raw token, record contents or caller-selected credential record into a public fill/typing tool.

Private preparation is not successful login. Verify the resulting account/page through permitted nonsecret state after the private operation releases protection. Preserve the original attempt and use its recovery/status tools after uncertainty. Do not reapply a credential just because the page is unchanged. A missing/ambiguous credential may require the user's local Vault selection; never ask them to paste a secret into chat. MFA, CAPTCHA or security prompts follow their actual runtime requirements.

OAuth/SDK authentication is separate from UI password entry. If explicitly requested, use the service's documented private exchange and verified endpoint; do not treat an SDK key as an access token or guess endpoints with credentials attached. Keep credential files and token contents outside task artifacts, logs and commit history. Do not retry rejected credentials without new evidence or explicit steering.

Permanent Mechanize consent is matched to its verified client, scope and modes. Reuse it across sessions when valid. Credential protection, macOS grants and server identity remain distinct. A denied/unknown private operation cannot be bypassed with Computer Use, clipboard reads or screenshots.

Distinguish missing Vault configuration from missing app consent. An installed
credential tool is not proof that its private store is configured, contains one
matching record, or has completed a login. Use the returned preparation/status
code to identify the actual requirement. `needsConfiguration` calls for local
Vault setup or record selection, not another Chrome approval. Preserve an existing
authenticated session and continue independent work while that requirement remains.
Do not configure a new custody provider, migrate keys, import credentials or widen
access merely to make a qualification test pass. Use the user's authorized local
setup path, and keep any credential entry in that private interface.

When the user authorizes an existing encrypted Scy Basic resource and the native
panel supports it, use Vault → Create secret → Import encrypted Scy resource.
Enter only the source basename and verified exact HTTPS origin, then import
through the protected native transaction. The local CLI decrypts directly into
the one-shot encrypted-record flow; never reveal its output in chat, public input
tools or logs. Require a private owned source and the supported local cipher.
Reject OAuth/SDK resources as website passwords. Preserve failed/uncertain writes
and inspect before retrying; an import does not prove successful sign-in.

After a broker redeployment, select the current exact tab and attempt a fresh
public read. Extension 0.1.87 supports a short-lived public-read fence across a
broker restart while retaining the original mutation binding and receipts.
The document, permission scope and public-page classification must still match;
known-value redaction remains required after private credential entry. A passing
read does not qualify input or a fresh login. Do not repeat credentials, reload
the page or request new consent merely because the broker restarted.

If `publicReadIdentityChanged` persists on an older renderer, first inspect the
extension version and current tab identity. If the original credential
submission is confirmed, independent
native inspection verifies the expected signed-in dashboard, and no input is
pending or unknown, one normal reload of that exact non-editing page can create a
fresh renderer binding. Preserve the original credential receipt and requalify
the resulting document through Mechanize. Do not reload an unsaved form, repeat
login, clear credential protection or treat this as a remedy for denied access.
Record the native recovery separately from subsequent Mechanize reads; a passing
read does not qualify plan creation or a new login's automatic handoff.

## Secure Input blocks native control

When native capabilities report `nativeControlUnqualified`, distinguish runtime
readiness from consent before requesting another grant. On macOS, a read-only
Secure Input check and `kCGSSessionSecureInputPID` can identify an owning process
without reading its window, password field or credential values. Secure Input
being enabled does not prove the screen is locked or that a password was entered.
Verify the process identity before naming the owning app.

A separately launched helper's doctor result is not evidence of the broker's
permissions: its launch identity, Accessibility grant and authenticated channel
can differ. Use live MCP capabilities for the actual automation route; use the
standalone check only for independently applicable system state.

If Secure Input is active, first distinguish an unfinished private operation from
ordinary browser focus. When the private operation is terminal, no input is pending
or unknown, and the browser route remains independently qualified, a normal
activation of the already verified public task tab is a permissible recovery step.
It must preserve other tabs and drafts and must not dismiss or interact with an
unidentified credential prompt. Check system state and native capabilities after
that action; successful browser activation does not prove Secure Input cleared.
When an authorized native diagnostic route shows Chrome retaining password focus,
ordinary address-bar focus (`Command+L`) can release that focus without changing
the URL, reading a password, submitting the form or closing any tab. Use it only
after the private input operation is quiescent; never type or paste into the
address bar during this recovery. A page-body click or activating another tab may
leave Secure Input active. Verify the focused control and then recheck Mechanize's
native capabilities before input. This is normal focus recovery, not permission
to disable the OS protection or bypass an ungranted app scope.
If protected entry remains active, let the user finish or dismiss it and bring the
intended app forward. Do not disable Secure Input, terminate its owner,
reset permissions, or switch executors to bypass the protection. Preserve pending
private-operation receipts. After the user action, recheck Secure Input and live
capabilities, then observe the intended window before resuming. A cleared Secure
Input flag alone does not prove native editing, saving or export is ready.
