# Authenticated consent broker

`consent.Service` is protocol-neutral. The host binds `Options.Namespace` to the verified principal and injects a fixed per-user Datly invocation callback plus verified client, separate human/admin actor, current enrolled client/session lookup and ceiling/TCC policy callbacks. Every callback is required. The UI transport owns its private socket, signed-peer/credential verification and Scy enrollment. A caller-selected display name, namespace, target alias or session does not establish authority.

`CreateRequest` validates an exact application/window/origin target, observe/control/record modes, bounded purpose and duration, and the current principal/operator/helper ceiling. `Decide` requires a separately authenticated human administrator, re-resolves the bound client/session, checks expiry and ceiling, and commits an atomic CAS decision with append-only audit. Deny creates no visible grant. Immutable request identity, target, modes, purpose and duration cannot widen during a decision.

`Host.AuthorizeOperation` is called on host observation and Endly step execution before the native or Chrome backend is invoked. It derives an exact app/origin scope from the step surface and requires the grant, session and purpose binding from authenticated request context. Once grants are durably consumed by generated `ConsumeOnce` CAS before a lease is returned; losing contenders fail closed. Session grants stay bound to the original verified client/session and expiry. The returned `Lease.Context` is passed to the backend and cancels at expiry or revocation. The dispatch adapter must observe cancellation before each input and call `Lease.Release` only after stop and cleanup are confirmed. A helper disconnect with uncertain cleanup must call `CleanupUnknown`, never `Release` as if cleanup succeeded. Current host execution releases leases on `notDispatched`; dispatched/unknown results still need lifecycle reconciliation that proves stop and releases or marks cleanup unknown. The Endly fixture tests explicitly model cancellation and release after stopping, not the real helper cleanup path.

`Revoke` inhibits new and admitted operations immediately, persists `requested`, advances to `stopping` on reconciliation and returns `revoked` only after every admitted lease has released with cleanup confirmation. `Snapshot` reconciles requested/stopping states. Grants recovered after broker restart have no in-memory cleanup proof and remain `cleanupUnknown`; an empty local registry cannot prove an old helper stopped. Keep one exclusive broker instance per desktop and one service per authenticated namespace. A second service instance cannot safely stand in for an authoritative live helper registry.

Persistence consists of six generated private Datly use-case components: `consentcreate`, `consentrequests`, `consentdecide`, `consentgrants`, `consentconsume`, `consentrevoke`. Schema migration 003 adds the consent record and immutable audit graph. Hooks require host-issued contextual authority and compare every resulting column to the authorized record; a nested audit hook rejects updates to existing audit identities. All component routes remain private and are linked by `data/host.Open`. Confirmed transaction completion is mandatory for every grant/consume/revoke result. Read lists cap at 200 recent records; exact request/grant lookup is independently filtered in SQL and cannot lose an older identity because of this cap.

`go test ./consent ./data ./data/host` uses disposable schema fixtures and real generated Datly SQLite components. `host/consent_test.go` also drives the broker through an Endly fixture step and checks that revoke cancels its lease, then separately verifies once-consumption. These tests perform no app launch, desktop input, permission prompt or live TCC action. They prove actor separation, exact target/purpose/session binding, once CAS races, ceiling rechecks, denial, expiry and fixture cancellation/cleanup uncertainty. They do not prove signed installation/enrollment, real helper cancellation or live macOS permission state; the host must supply and qualify those boundaries.
