# Datly data components

All product persistence is generated by Datly v1 from `source/*/*.dql` and adjacent `sql/` assets. Generated orchestration is never edited. Authored `authorization.go` and create-once `lifecycle.go` enforce trusted namespace and business invariants. `Provision` is the narrow infrastructure-only schema/connector path; its SQL execution applies embedded DDL and reads SQLite schema version metadata, never product rows.

`host.Open(ctx, sourceRoot, storageRoot, scope)` returns a Datly standalone server with a fixed per-user connector and no listener. Retain at most the configured host user capacity, shut down before eviction, and never modify a connector DSN. The source module must remain deployed at `sourceRoot`; a copied binary alone is not a deployment.

After verified authentication, the host calls `data.WithScope` with its opaque 64-hex namespace and broker-granted lease epoch. Supply that namespace explicitly through every generated input setter. Caller request fields never select identity or storage locations. All internal callers use generated input/entity setters so supplied zero values and sparse fields retain presence.

Invoke `server.InvokeComponent` with `exec.ComponentRequest`, an exact `spec.Key`/route and the generated input. `Completion` observes `handler.Outcome`. BeginAttempt dispatch is allowed only when invocation succeeds **and** `outcome.CommitConfirmed()` is true. Neither a successful queue nor caller-owned pending transaction permits native/browser input. No input occurs inside any data hook.

Components currently generated:

- `PublishPlanRevision` POST: immutable plan insert.
- `CreateRun` POST: authorized run insert.
- `LoadRun` GET: scoped run with attempts, effects, milestones and checkpoints for reconciliation.
- `BeginAttempt` PATCH: run CAS plus attempt/intent/event graph; one attempt, current lease epoch, no unresolved effect, no reused attempt. Token advancement is explicit in Init. The caller supplies run identity, expected revision and the typed nested intent/audit graph.
- `CommitOutcome` PATCH: effect CAS plus milestone/event graph; immutable run/attempt/business identity and intent/unknown-to-confirmed/absent/unknown transitions. Supply AttemptId and RunId to resolve child links. One audit event is required.
- `PublishCheckpoint` PATCH: guarded run CAS + immutable checkpoint publication, checking scoped manifest hash/ownership, plan/revision/event cursor, unresolved effects and every read-only published artifact reference against trusted byte evidence.
- `PublishArtifact` POST: immutable published metadata after trusted scoped file verification.
- `TransitionRun` PATCH: guarded paused/terminal status with CAS and new audit event; unresolved effects block safe transitions.
- `AttachOperation` PATCH: immutable Endly session/operation correlation, CAS and new audit event.
- `ListRuns`, `LoadPlan`, `ListEvents`, `ListCheckpoints` GET: authorized catalog readers; list projections currently cap at 200 rows.
- `StateGet` GET: scoped variables, revision, milestones, unresolved effects and checkpoint metadata.
- `StatePatch` PATCH: CAS revision plus typed user variables only; requires a trusted paused/new runtime permit, rejects active run state and every unresolved effect, and cannot modify ledger/objective/history. Omitted variables remain unchanged.
- `AppendRecordingEvents` POST: bounded 256-row semantic event batch; unique recording/sequence keys enforce ordering identity. Recording capture/redaction remains the recorder's responsibility.

Regenerate with `DATLY_BIN=/path/to/datly DISCOVERY_DB=/path/to/schema.sqlite data/scripts/regenerate.sh`. The CLI's schema discovery opens SQLite read-only. Provision the fixture separately with schema/001.sql and schema/002.sql. Regeneration preserves authored hooks; never hand-edit generated files.

The runtime acceptance test actually executes generated SQLite operations for plan, run, BeginAttempt and CommitOutcome, checks confirmed commit evidence, rejects unresolved-effect replay and cross-user bound input. Additional requirements remain: authoritative plan hashes, per-object grants, atomic initial CreateRun audit/correlation, immutable-plan repair, retention/artifact components, connector eviction/reopening policy, crash injection, malformed/large recording payload policy, source-backed packaging and real two-user desktop lease evidence. No production-completeness claim is made.

State schema version 2 adds run_variables with complete namespace/run/name keys. Infrastructure provisioning migrates version 0/1 fixtures, rejects a future version, and commits migration 002 with its version metadata atomically. StatePatch bounded values are validated as model.Value JSON; user keys are simple identifiers. Safe runtime state mutation is an explicit host capability and defaults unavailable. Read projections are serialized within one host's user admission lock; no multi-process reader snapshot guarantee is claimed.

Checkpoint manifests are bounded to 1 MiB and 1...128 immutable artifact references. The host performs filesystem verification before invoking generated mutation; hooks compare detached trusted evidence and generated Previous metadata only. Missing artifacts, false hashes/ownership, wrong revision/cursor, reused checkpoint identity and unresolved effects fail before commit. Auxiliary artifacts/events/effects remain read-only. The small auxiliary table declarations stay inline because this connected transcriber does not retain their discovered primary-key authority when hidden inside an embed asset.

Schema version 3 adds `consent_records` plus append-only `consent_audit`. `consentcreate` POST, `consentrequests`/`consentgrants` GET and `consentdecide`/`consentconsume`/`consentrevoke` PATCH are generated private use-case components. Complete scoped record identity and CAS revision guard every transition, immutable audit writes share the transaction, and authenticated broker authority is explicit in hooks. Exact reader identity filtering precedes the 200-row catalog bound. See [consent broker](../consent/README.md) for the host callback and per-operation cancellation contract. Regeneration discovery fixtures must apply schema 003 as well.
